Findings resolved during the review:

- The initial 640px cue threshold could miss overflow from large valid amounts. The main session reproduced this with 22 entered movements. The final `ForecastTableViewport` instead compares rendered scroll/client widths, observes both region and table, remeasures on children changes, and provides a resize fallback. Observer/listener cleanup is present. In supplied `boundaries-result.json`, the final large-value table has a 715px scroll width inside 640/641/668px regions; the cue and description remain present at every width. The final image corroborates the large-value case. Returning to smaller values removes both, and the no-ResizeObserver fallback is reported as passing. Resolved.
- The original always-present `aria-describedby` could expose hidden scrolling instructions when the table fit. The final implementation sets both the cue’s `hidden` state and the section’s description from measured overflow. `final-result.json` records the description present at overflowing widths and absent when the ordinary-value table fits. Resolved.
