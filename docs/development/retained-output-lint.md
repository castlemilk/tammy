# Retained output and source lint

The repository retains historical capture bytes as well as maintained source under
`output/`. Do not treat the whole directory as generated or exclude it from lint.

The 55 exact paths in `compliance/retained-output-lint.json` are the imported October
2026 captures at base `aeda631070f9cb44289658c52128c595bf6133f7`:

- 52 JSON records from dated income/BAS and purchase/GST capture runs;
- the accepted purchase snapshot's `artifact-audit.mjs` capture helper;
- the historical invoice demo's `seed-demo.ts` and generated `seed-demo.mjs` bundle.

They are archival capture inputs/results, not current-main implementation or generic
examples. The invoice source and run script refer to an old absolute issue-worktree
path and its app package. The bundled file includes generated React/protobuf code.
Its existing `run-seed.sh` bundles that historical source with esbuild before running
the synthetic demo. Do not execute that script merely to format retained output.

Formatting is not a safe cleanup here. For example, the BAS `evidence.json` records
the byte hashes of the comparison JSON, and accepted purchase `evidence-files.json`
records the audit helper and acquisition artifacts. Changing whitespace invalidates
those records. Rerunning an old acceptance capture against current source would also
change its provenance. No archived file is modified or regenerated by this policy.

`pnpm lint` first streams and checks the SHA-256 of every retained path. It then runs
the unchanged recommended Biome rules on source, excluding only those exact archived
paths. The checker requires a one-to-one match between manifest paths and Biome's
output exclusions. Missing files, changed bytes, broad globs and non-output entries
fail. Exact-path `-text` Git attributes also preserve these bytes under Windows
`core.autocrlf=true`; their scope must match the same inventory. A real Git checkout
regression fails without these attributes (LF becomes CRLF) and passes with them.
This replaces inappropriate source formatting of these bytes with preservation
checks; it does not turn off checks for new output files.

New scripts, demos, capture JSON and all other output paths still receive normal
Biome checks. Regression tests explicitly send faulty new TypeScript and JSON under
`output/` through the real pinned Biome executable and require failure, then verify
the corrected fixtures pass.

For a new capture, use its existing producer and retain truthful source/package
provenance. Prefer a new dated output path rather than rewriting a historical run.
An intentional update to an archived path requires reviewing its generator, every
referencing hash record and the preservation manifest together. Do not update a hash
merely to hide an unexpected change.

The original lint backlog was 861 errors, 387 warnings and 646 infos across these
55 files. The generated invoice bundle accounted for 805 errors; its historical
TypeScript source accounted for two. There were no cache diagnostics. The separately
tracked `.pnpm-store` is unchanged, and all local cache files remain in place.

This change is isolated from the Soft Precision PR. It has no renderer, financial,
dependency, permission, release or deployment changes.
