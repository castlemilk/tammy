# SBR Desktop Simulator and E2E Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a signed-in local user inspect SBR readiness, securely import or replace a RAM machine credential, and run a deterministic non-network simulator while preserving the existing complete accounting walkthrough and the BAS preparation-only boundary.

**Architecture:** Add generated SBR and required identity RPCs to the existing bounded Electron IPC/preload bridge, then add one Settings → SBR readiness screen. The native chooser path is held briefly only by trusted Electron main and forwarded through the authorized core operation to the helper; renderer never receives it, and Electron/core never open or parse credential bytes. Password/TOTP/Product ID are transient UI inputs and are never persisted or logged; authoritative buffer zeroing occurs in the helper. The simulator consumes only canonical synthetic data. Packaged E2E proves setup, accounting, credential lifecycle, restart/unlock, zero sockets, and clean process exit. EVTE UI is status-only until external signed registration/component evidence exists.

**Tech Stack:** Electron, React, TypeScript, Vitest/Testing Library, Playwright, generated Connect protobuf codecs, existing Tailwind/component patterns, Go core integration.
